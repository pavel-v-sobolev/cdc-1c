# Запуск из окружения: переменные `CDC1C_*`

Режим, в котором cdc-1c работает **без единой строки вашего кода**: параметры задаются переменными
окружения, точка входа готова. Запускается командой `cdc-1c` либо как модуль:

```bash
cdc-1c
python -m cdc_1c     # то же самое
```

В контейнере это поведение по умолчанию: не смонтирован `/config` со своим `runner.py` — работает
именно этот режим (см. [README](README.md), «Запуск в docker»).

## Что этот режим умеет и чего не умеет

Умеет ровно то, что делает `Replicator1C`: читает изменения из 1С через OData и план обмена и
пишет их в целевую БД, подтверждая приём пакета только после успешного сохранения. Плюс полные
выгрузки объектов, которые встали в очередь (новый объект, заказанная перевыгрузка).

Не умеет ничего, что объявляется кодом:

- **обработчики** (витрины поверх загруженных таблиц) — их классы надо где-то написать;
- **полные выгрузки по расписанию** (`FullLoadCron`) — состав расписаний тоже задаётся кодом;
- **несколько планов обмена** в одном процессе.

Понадобилось что-то из этого — берите шаблон [config/runner.py](config/runner.py): там та же сборка,
только явным кодом, и всё перечисленное добавляется раскомментированием. Переменные окружения при
этом никуда не деваются — шаблон читает те же самые.

## Переменные

### Обязательные

| Переменная | Значение |
|---|---|
| `CDC1C_ODATA_URL` | адрес OData-интерфейса базы 1С, например `http://server/base/odata/standard.odata` (именно интерфейса, а не базы) |
| `CDC1C_EXCHANGE_NAME` | имя плана обмена в 1С — то, что видно в конфигураторе |
| `CDC1C_DB_URL` | строка подключения SQLAlchemy к целевой БД, например `postgresql+psycopg2://user:pass@host:5432/dwh` |
| `CDC1C_QUEUE_GUID` | `Ref_Key` узла обмена (очереди) |

`CDC1C_QUEUE_GUID` формально можно не задавать: чтение изменений тогда выведет в лог список узлов
плана обмена и остановится — guid берётся оттуда, без похода в 1С. Как единственный обязательный,
который разрешено оставить пустым, он и не проверяется на старте.

### Необязательные

| Переменная | По умолчанию | Значение |
|---|---|---|
| `CDC1C_ODATA_USER` | — | пользователь OData; не задан — запросы идут без авторизации |
| `CDC1C_ODATA_PASSWORD` | пусто | пароль этого пользователя |
| `CDC1C_DB_SCHEMA` | схема БД по умолчанию (`public` у Postgres) | схема, в которой создаются таблицы данных |
| `CDC1C_DB_TEMP_SCHEMA` | схема данных | схема промежуточных таблиц merge |
| `CDC1C_FULL_LOAD_WORKERS` | `2` | число фоновых потоков полной выгрузки |
| `CDC1C_POLL_INTERVAL` | `60` | период опроса изменений, секунд (только в режиме `loop`) |
| `CDC1C_MODE` | `loop` | `loop` — вечный цикл; `once` — один цикл read → save → notify и выход |
| `CDC1C_LOG_LEVEL` | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` / `CRITICAL` |
| `CDC1C_RUNNER` | `/config/runner.py` | **только в контейнере**: путь к своему runner'у, если он назван иначе |

Про `CDC1C_DB_TEMP_SCHEMA` стоит сказать отдельно: своя схема для рабочих таблиц merge удобна тем,
что в ней по определению нет ничего ценного. Таблицу, оставшуюся после падения процесса, там видно
и не жалко удалить, а таблицы с данными она не засоряет. Схему создаёт сам dbmerge.

`CDC1C_FULL_LOAD_WORKERS` влияет и на пул соединений: entrypoint заводит `create_engine` с
`pool_size = CDC1C_FULL_LOAD_WORKERS + 2` — соединение одновременно держат цикл изменений, поток
отметки живости незавершённых merge и страницы полной выгрузки (подробнее —
[README_HANDLERS.md](README_HANDLERS.md), раздел «Сколько нужно соединений к БД»).

### Не `CDC1C_*`, но важна

| Переменная | Значение |
|---|---|
| `TZ` | часовой пояс процесса, например `Europe/Moscow` |

В контейнере время по умолчанию UTC. На чтение изменений это не влияет, но расписания
`FullLoadCron` считаются в локальном времени, поэтому в конфигурациях с расписаниями `TZ` задавать
обязательно.

## Ошибки конфигурации

Проверяются на старте, до соединений с 1С и БД, и сообщают о себе одной строкой — без трейсбека:

```
CDC1C_ODATA_URL is not set (required: CDC1C_ODATA_URL, CDC1C_EXCHANGE_NAME, CDC1C_DB_URL)
CDC1C_POLL_INTERVAL='xx' is not a number
CDC1C_FULL_LOAD_WORKERS='-1' must be positive
Unknown CDC1C_MODE='step' (expected 'loop' or 'once')
Unknown CDC1C_LOG_LEVEL='TRACE' (expected DEBUG/INFO/WARNING/ERROR/CRITICAL)
```

Так же ведут себя недоступные БД и 1С — вместо полутора сотен строк трейса сквозь SQLAlchemy или
requests выводится причина:

```
cannot connect to the database postgresql+psycopg2://user:***@dbhost:5432/dwh: could not translate host name "dbhost" to address: Name or service not known
1C is not available at http://server/base/odata/standard.odata: ... [Errno 113] No route to host
```

Пароль в адресе БД при этом скрыт: строка попадает в лог.

## Примеры

Локально, разовая проверка доступов (один цикл и выход):

```bash
CDC1C_ODATA_URL="http://server/base/odata/standard.odata" \
CDC1C_ODATA_USER=odata CDC1C_ODATA_PASSWORD=secret \
CDC1C_EXCHANGE_NAME="ДляODATA" \
CDC1C_QUEUE_GUID="a9bc23c5-3689-11f1-926c-0800270bc6cb" \
CDC1C_DB_URL="postgresql+psycopg2://user:pass@localhost:5432/dwh" \
CDC1C_DB_SCHEMA=cdc_1c CDC1C_DB_TEMP_SCHEMA=cdc_1c_tmp \
CDC1C_MODE=once \
cdc-1c
```

В контейнере те же переменные передаются ключами `-e` либо перечисляются в
[docker-compose.yml](docker-compose.yml) — там к каждой есть комментарий, и настройка читается
одним экраном. Полные команды запуска — в [README](README.md), раздел «Запуск в docker».
